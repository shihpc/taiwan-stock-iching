### A2 兩個指標邊界（取代 §4.2 五爻 D 與 §4.3 序 1，補 §4.1a）

#### A2.1 融資：先判近零，再判增減

判定為有序 if–elif（令 r ＝融資餘額期間變化率）：

| 序 | 條件 | 分數 |
|---|---|---|
| 1 | **\|r\| < 0.5%（近零，最先判）** | 50 |
| 2 | r ≥ 0.5%（資增）且期間報酬 > 0 | 50 |
| 3 | r ≥ 0.5%（資增）且期間報酬 ≤ 0 | `S(−r)`，值域 7.30 – 47.88 ※（2026-09-08 交叉檢查更正：原寫 50 為算術誤植） |
| 4 | r ≤ −0.5%（資減） | `50 + 0.5 × [S(−r) − 50]`，值域 51.06 – 71.35 ※（2026-09-08 交叉檢查更正：原寫 50 為算術誤植） |

※ **兩組皆在 `S` 的原生值域上，`N` 對其為恆等映射**（2026-09-08 補記）：全案所有轉換自該日起統一過 `N(v; lo, hi)` 映射到 [7.30, 92.70]（見 `P1-B1-market.md` §B1.0／`P1-B2-params.md` §B2.0「轉換值域統一」節），而 `S` ＋ `clip_3d` 的原生值域**即為** [7.30, 92.70]，故此兩組數值**不變**。**特別注意**：序 4 的 `50 + 0.5 × [S(−r) − 50]` 所產生的窄區間 [51.06, 71.35] 是**刻意的半幅壓縮**（融資減不必然偏多，只給一半的偏多幅度），**不是另一個原生值域**——**不得**把它當成 `[lo, hi] = [51.06, 71.35]` 去套 `N` 拉伸回滿幅，那會抹掉這條規則的全部用意。

原文「資增／資減」與「\|r\| < 0.5%」條件重疊，現由序位解決：近零永遠先判，序 2–4 的資增／資減條件因此不再涵蓋近零區。

#### A2.2 縮量回檔：排除回撤為零

四爻情境表序 1 條件改為：

> 二爻分 ≥ 55 **且 `0 < 5日回撤_t ≤ 2`** 且 量比 < 0.8 且 `C_t ≥ MA20_t`

理由：原條件 `5日回撤 ≤ 2` 在回撤＝0（今日即為近 5 日最高收盤）時也成立，那是**低量續漲**不是回檔。回撤＝0 者落入序 4 一般縮量＝50。情境名稱維持「縮量回檔」（原意即為回檔）。

#### A2.3 分母無效與資料缺漏分開

`ATR14_{t−1} = 0` 或 `VMA20_{t−1} = 0` → 該指標**分母無效**，計為缺值但原因碼為 `denominator_zero`，與 `missing`（抓取失敗或來源未提供）**分開統計**。覆蓋率報表分列兩者，避免把「長期無量」誤報成管線抓取失敗。此規則寫入 §4.1a 的缺值欄位規範，適用所有含除法的子指標。

### A3 事件版本鏈（取代 §7.4 合併規則、§12.3 去重鍵段、§16.2 去重驗收）

**問題**：「欄位較完整者勝」跨版本比較時，舊公告的全文會贏過只有主旨的更正版，導致頁面持續呈現已被更正的金額或狀態。

#### A3.1 版本化事件模型

| 欄位 | 說明 |
|---|---|
| `event_id` | 穩定識別（去重鍵計算所得），跨版本不變 |
| `version_no` | 1, 2, 3…，同一 `event_id` 內遞增 |
| `version_id` | `event_id#version_no` |
| `content_hash` | 正規化後內容雜湊，決定是否算「內容變更」 |
| `status` | `active` / `superseded` / `withdrawn` / `resolved` |
| `supersedes` | 指向前一版本的 `version_id` |
| `relates_to` | 跨事件關聯（進度、衍生事件） |
| `fulltext_missing` | 該版本是否缺全文 |

#### A3.2 三條規則

1. **欄位完整度只在同一版本內比較**：同一 `version_no` 可能同時由 CSV（有全文）與 mopsov（只有主旨）取得 → 合併取較完整者。
2. **跨版本一律版本序決定**：更正、撤回、解除都新增版本，`version_no` 較大者為現況，**即使新版本只有主旨也勝出**（此時 `fulltext_missing=true`，頁面標示「更正版全文尚未取得」）。舊版本 `status=superseded` 保留供追溯，不刪除。
3. **現況與 shadow 計分只讀最新有效版本**（`status=active`）；頁面可展開歷史版本鏈。

#### A3.3 冪等相容

- `revised_at` **只在 `content_hash` 改變時更新**；內容未變則不寫入、不 commit，與「冪等重試不產生新 commit」不再矛盾。
- 重跑紀錄另存 `runs/`（本來就不進事件檔），不影響事件版本鏈。

### A4 排程序列化補 `queue: max`（取代 §12.3 第一條、§16.2 序列化驗收）

**已查證**（GitHub Actions workflow syntax 官方文件，2026-09-08）：`concurrency` 的 `queue` 屬性預設為 `single`——「同一併發群組中最多只有一個工作或工作流程執行可處於 pending；新工作排入時，同群組中既有的 pending 工作會被取消並取代」。`queue: max` 則允許最多 100 個 pending，滿了才取消後續者。**另有一條限制：`queue: max` 與 `cancel-in-progress: true` 不可併用，會導致驗證錯誤**；本專案用 `false`，相容。

採用：

```yaml
concurrency:
  group: data-write
  cancel-in-progress: false
  queue: max
```

**驗收改寫**（不能只檢查有無宣告）：

| 條件 | 量法 | 門檻 |
|---|---|---|
| 每次觸發都有結論 | 連續 10 個交易日，比對「排定觸發數」與「實際完成數」，逐次記錄結論（success／failure／cancelled／skipped） | 無「無紀錄」的觸發 |
| 取消者必補跑 | 任一 `cancelled` 的觸發，須有後續補跑並成功 | 補跑成功率 100%；未補跑即不通過 |
| 遺漏偵測 | 對照 cron 排程表與實際 run 清單 | 缺席者必有原因碼（休市、上游未齊、平台故障） |
| 宣告檢查 | 靜態檢查 workflow 檔含 `queue: max` 且 `cancel-in-progress: false` | 100%，但**僅此不足以通過本節** |

### A5 交易限制的生效表述與方向適用（取代 §7.1 路徑 2、§7.5、§12.1、§16.4 生效列）

#### A5.1 統一表述（刪除所有「立即生效」）

> 收到並確認限制後，**不經 AI**，依生效時間更新資格；頁面顯示該類限制的「最後查核時間」。**第一版為定時收集，收集間隔內可能存在延遲，不保證公告發布當刻更新網站。**

v1.2.2 中「立即處理」「立即生效」「不晚於次一計分班」三種並存的說法一律以此句取代。

#### A5.2 限制類型 × 影響方向

**限制只影響其適用的方向**，放空限制不得自動移除做多候選。

| 限制類型 | 做多候選 | 做空候選 | 個股頁 |
|---|---|---|---|
| 停牌／暫停交易 | 移除 | 移除 | 顯示並標示 |
| 終止上市（下市） | 移除 | 移除 | 移出股票池 |
| 處置（分盤交易、預收款券） | 移除 | 移除 | 顯示 |
| 注意股 | 保留＋旗標 | 保留＋旗標 | 顯示 |
| **平盤下不得放空** | **不影響** | 移除，或降級為做空研究候選 | 顯示 |
| **停止融券／信用交易停止** | **不影響**（若同時停止融資另標，仍不移除做多） | 移除 | 顯示 |
| 融券最後回補日將至 | 不影響 | 降級為做空研究候選 | 顯示回補日 |

#### A5.3 解除不自動恢復推薦

限制解除**只移除該限制旗標**。該股必須在下一次計分中**重新通過方向門檻、風險層與流動性條件**，才會再度出現在候選名單；不得因解除就直接恢復原本的推薦狀態。解除事件本身依 A3 記為新版本。

2. **四種失效對應本規劃**：v0.2 的敘事待複核／結構解釋失效／交易資格失效／資料解釋失效四層，分別對應：分數下降但未翻爻（保留正式卦、降低文案確定性）／正式翻爻（重寫核心矛盾）／**走本清單 A5 的規則**／必要資料失效（顯示最後有效卦與時間，不生成今日正式卦）。
3. **爻位語意分離**：v0.2 §1.2 明列個股與大盤同一爻位是不同證據（例：個股二爻＝價格趨勢，大盤二爻＝市場廣度）。文案生成必須依市場別選用對應語意，**不得共用同一句模板**。
