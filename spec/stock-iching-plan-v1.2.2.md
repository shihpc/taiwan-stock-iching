## 4. 指標與評分

> **⚠ 本節（§4）與 §5 已被 P1 交付文件取代（R5d 聲明）**：凡與 `P1-B1-market.md`／`P1-B2-params.md` 重疊的參數表與權重，**一律以 P1-B1／B2 為準**，本節原文保留僅作沿革、**不得據以實作**。已知衝突點列於四份 P1 文件開頭的「優先序」段。


### 4.1 共用定義與轉換函數

**時間基準（避免自我參照）**：所有以 T 日收盤後計算的指標，波動與均量基準一律取 T−1 日為止的值。

- `ATR14_{t−1}`＝以 T−1 為止 14 日計算的平均真實波幅。
- `VMA20_{t−1}`＝T−1 為止 20 交易日均量（不含當日）。
- `量比_t = V_t ÷ VMA20_{t−1}`。
- `日變動_t = (C_t − C_{t−1}) ÷ ATR14_{t−1}`（無因次，正為漲、負為跌）。
- `5日回撤_t = (max(C_{t−4..t}) − C_t) ÷ ATR14_{t−1}`（無因次，非負）。

**轉換函數**：

- **S(x)**＝100／(1＋exp(−k(x−c)))。**尺度 d 定義為「分數由 50 升到 70 所需的 x 變化」**，k＝ln(7/3)/d ≈ 0.847/d。**S 本身只定義轉換，不含截斷**；截斷由各指標的 `clip_policy` 決定（§4.1a）。
- **P_hist(x)**：該股自身近 250 日百分位，只用於「相對自身的極端程度」，**不把持續為負的值變成正向支持**。
- **P_cs(x)**：當日全池百分位，只進排名層與旗標，不進爻分。

### 4.1a 截斷政策（勘誤 1 修正：逐指標明定）

| 政策 | 定義 | 適用 |
|---|---|---|
| `clip_3d`（**預設**） | 送入 S 之前先把 x 截在 `[c−3d, c+3d]` | 全部 S 轉換的子指標 |
| `none` | 不截斷，須逐項寫明理由 | 目前**無**指標採用 |
| `n/a` | 不經 S（離散映射、線性映射、百分位） | 結構、延續、收盤位置、產業家數比、P_hist、P_cs、大盤方向分數、創高下限（`max(base, 84.16)`）|

- 採 `clip_3d` 後，**S 的有效值域固定為 [7.30, 92.70]**（因為 k·3d ＝ 3·ln(7/3) ＝ 2.542）。所有由 S 導出的分數上下限都要照此計算，不得再引用未截斷的極限值。
- **兩個必須用未截斷原值的地方**（截斷只作用於送入 S 的 x，不改變判斷條件）：
  1. **情境門檻**：四爻情境表的「量比 ≥ 1.3」「日變動 ≥ 0.5」「5日回撤 ≤ 2」「量比 &lt; 0.8」等條件，一律用原值判定。
  2. **旗標判定**：三爻過熱旗標的「(C − MA20) ÷ ATR &gt; 3」、風險層的「追價」「異常長黑」「乖離 3 ATR」，一律用原值判定。
- **截斷不生效的指標**須註明：五爻 C 持續性——**三期間各自檢查**（2026-09-08 交叉檢查更正：原僅舉短線單例）：
  短線 值域 [−2.5, +2.5]／d=1.0→[−3, +3]；波段 [−5, +5]／d=2.0→[−6, +6]；中期 [−10, +10]／**d=3.34**→[−10.02, +10.02]。三者皆滿足 `3d ≥ 原始值域上界`，截斷永不觸發。**中期的 d 原為 3.00（3d=9 < 10）會觸發，已改 3.34**，見 `P1-B2-params.md` §B2.5。
- **此宣稱的成立前提是各持續性子指標的 d 必須滿足 3d ≥ 原始值域上界**（見 B2 §B2.5）。
- **`n/a`（不經 S）的轉換並非不受規範**（2026-09-08 R5 補，R5b 修訂）：離散映射、線性映射 `L`、`P_hist` 百分位等的原生值域與 S 不同（`L` 為 [10, 90]、`P_hist` 與情境表為 [0, 100]），它們改由正規化函式 **`N(v; lo, hi) ＝ 7.30 + (v − lo) ÷ (hi − lo) × 85.40`** 統一映射到與 `clip_3d` 相同的值域 **[7.30, 92.70]**。
  - **`P_cs` 是唯一例外，不套 `N`**（R5b 更正：本條原把「百分位」整類納入，與 B1 §B1.0／B2 §B2.0 政策第 6a 點衝突）——`P_cs` 只進排名層與旗標、不進爻分，其消費端全是原生 0–100 門檻（`P_cs ≥ 95`、依 `P_cs` 取前 N 名），套了 `N` 會讓 95 變 88.43 而門檻仍寫 95。
  - **`S` ＋ `clip_3d` 與已由正規化分數加權而得者（如大盤方向分數）：`N` 為恆等映射，不得重複套用。** 融資族 D 序 3／4（`S(−r)` 的直接輸出與其半幅仿射）即屬此類。
  - `N` 保持中性點在 50（`N(50)=50.00`），故陰陽門檻 50、`F-臨界` [45, 55]、內外卦 ≥55／≤45 的**數值**不改寫。**但「50 不動」不代表「45／55 的判斷等價」**（R5b 使用者裁定，撤回本條原先「全部維持不變」的說法）——不動點不保證分數**跨越**門檻的頻率與時點不變，而陰陽態、遲滯、旗標、內外卦吃的正是跨越行為；**所有因縮放而改變的門檻行為一律須重新驗證**，見 §16.5「門檻行為重驗」列。
- 每個指標在參數字典中都必須有 `clip_policy` 與 `native_range` 欄位；P1 交付時逐項填寫並由子代理核對「文件宣告的值域＝程式實際值域」。

- 樣本 B 若某週超過 30 則，全數納入，不受 30 則限制；三個樣本的重複事件只標註一次、不重複計數。
- **只複核模型已判重大者無法發現漏判**，故樣本 C 為必要項；沒有樣本 C 的一致率不得作為品質結論。
- **樣本 C 估的不是召回率（勘誤 2）**：從「模型未判重大」的池抽樣，估的是 P(實際重大 \| 模型未判重大)，即漏判比例；召回率是 P(模型判重大 \| 實際重大)，兩者分母不同，**即使累積 200 則也不能直接換稱召回率**。第一版只報漏判數、抽樣數、比例與 Wilson 區間。
- 表述限制：一致率與精確率是**樣本估計值**，須附樣本數與信賴區間；不得表述為「整體零錯誤」「全部正確」或「召回率」。
- shadow 分數展示條件：樣本 A 一致率 ≥ 85%、樣本 B 精確率 ≥ 80%、樣本 C 當週漏判 ≤ 1 則。未達標只展示事件、不展示 shadow。

### 7.6a 召回率的選用二階段推估（第一版不做）

若日後確實要估召回率，須結合兩個樣本並傳遞不確定性，不可由單一樣本得出：

1. 真陽性 TP ≈ 精確率(樣本 B) × N(模型判重大)。
2. 漏判總數 FN ≈ 漏判比例(樣本 C) × N(模型未判重大)。
3. 召回率 ≈ TP ÷ (TP + FN)，區間須同時傳遞樣本 B 與樣本 C 兩段抽樣誤差（例如以 bootstrap 或 delta method）。
4. 報告必須同時列出 N(模型判重大)、N(模型未判重大)、兩個樣本的 n 與區間；缺任一項不得宣稱召回率。
- Opus 5 複核 5% 與人工標註分別記錄；不一致案例進回歸集，每次改提示重跑。
- 標註者：使用者或指定人；Claude 可準備標註介面與樣本，但不能自標自驗。

### 12.2 持久保存與備份（勘誤 5 修正）

**先分清主存與備份**：

- Git repository 是**主存**。
- 相對 Hetzner 而言，GitHub 是**遠端副本**；相對 GitHub 主存而言，Hetzner 的 `git pull` 副本才是異地備份。
- **同一個 repo 內的 Release 資產不是獨立備份**，它與 Git 同存於 GitHub，同一帳號誤刪或帳號問題會一起消失。
- **`git pull` 不會拉取 Release 資產**，Release 必須另以 API 下載。

**三份分別保存**：

| 份 | 內容 | 位置 | 取得方式 | 保留 |
|---|---|---|---|---|
| 1 Git 狀態 | `data/state/`、`data/events/`、`data/latest/`、原始碼 | GitHub repo（主存） | Hetzner 每日 `git pull`（含完整歷史，可回復任一版本） | 全歷史 |
| 2 Release 資產 | 每日完整快照（latest JSON、state、當日 events） | GitHub Release（tag `snap-YYYYMMDD`） | Hetzner 每日以 API 另行下載（**不是 git pull**） | 本機保留 180 日；GitHub 端保留全部 |
| 3 校驗清單 | 每日 `manifest-YYYYMMDD.json`：檔名、大小、sha256、batch_id、commit sha | 同時存於 Release 資產、Hetzner、**第三處**（待決策：付費雲端儲存或使用者本機） | 三處各自產生後比對 | 全歷史（檔案很小） |

**Actions cache**：只加速可重建內容，不作任何主存或備份。

**還原能力要求**：

1. 從 Hetzner 副本可還原 GitHub 端（`git push` 復原＋Release 重新上傳）。
2. 從 Release 資產可重建 Hetzner 副本。
3. 校驗清單三處比對可偵測任一處的靜默損毀或誤刪。
4. **必須測試「GitHub 端資料誤刪後從另一份還原」**，不能只演練「從 GitHub 重建 Hetzner」。

### 12.3 並行寫入規則（勘誤 4 後段）

- 所有會 commit 的 workflow 共用 `concurrency: group: data-write`、`cancel-in-progress: false`，同一時間只有一個 job 在寫 repo。

- **衝突後重新讀取合併，不用覆蓋**：commit 前 `git pull --rebase`；若目標檔已被他人更新，**重新讀取該檔、以事件去重鍵合併後再寫**，絕不以本地版本整檔覆蓋。重試最多 5 次（沿 taiwan-flows `daily.yml` 前例），永不 force push。

## 13. 回測、預先登錄與驗收

### 13.1 資料截止與最後合格訊號日

資料截止＝2026-08-31（候選）。每個訊號有進場索引 `e = T + 1`、退出索引 `x = T + 1 + h`（交易日索引）。h 日標籤只對 `x ≤ 資料截止索引` 的訊號計算。以每年約 245 交易日估算（P1 用實際交易日曆重算）：

| h | 最後合格訊號日（約） | 保留段 2025-01 起有效交易日（約） |
|---|---|---|
| 5 | 2026-08-24 | 400 |
| 10 | 2026-08-17 | 395 |
| 20 | 2026-08-03 | 385 |
| 40 | 2026-07-06 | 365 |
| 60 | 2026-06-05 | 345 |

指標暖機**分兩軌**（2026-09-08 交叉檢查更正：原僅單軌 2020 年）：**價格類**（MA60、250 日歷史基準）回補 2020 年起；**基本面類**（營收加速度需 18 個月 ≈ 368 交易日 > 250）回補 **2019-06** 起。兩軌**皆不占評估期**。

### 13.2 切分與洩漏防護（勘誤 3a–3c 修正）

切分候選：訓練 2021-01～2023-06；驗證 2023-07～2024-12；最終保留 2025-01～資料截止（依 h 截斷）。P1 先列各段實際交易日數與股票數。

**兩個邊界都要 purge，且以實際索引逐樣本判定，不用「前 N 天」近似**：

| 邊界 | 規則 | 理由 |
|---|---|---|
| 訓練 → 驗證 | 訓練段中 `x ≥ 驗證段起始索引` 的樣本，排除於**訓練與參數估計** | 其前向報酬包含驗證段行情 |
| **驗證 → 保留** | 驗證段中 `x ≥ 保留段起始索引` 的樣本，排除於**調參與模型選擇** | 否則用 2024 年底訊號的未來報酬選模型，等於已看到 2025 保留段行情 |
| embargo | 驗證段與保留段起點後各 20 交易日的訊號不用於評估 | 降低序列相關殘留 |

- 每個邊界被排除的樣本數、比例，寫進報告。
- **年度角色須逐年標明**：用於挑模型的年度（例如驗證段內的 2024）**不得再稱為未參與選擇的獨立年度證據**。報告以表格列出每個年份屬於訓練、調參、或未見。
- 保留段只跑一次；任何規則修改後都不能再稱其為未見；新的未見段只能是之後累積的前向資料。

### 13.3 統計與「證據不足」（勘誤 3d–3e 修正）

- **IC**：每日 Spearman(方向分數, h 日前向報酬)，日序列均值；標準誤 Newey-West，lag 起點 h，另報 lag＝2h 敏感度。
- **分組報酬**：h 個錯開起始日子組合平均；報告資金占用、持倉重疊、換手、成本。
- **區間估計**：circular block bootstrap，區塊長度＝max(21, 3h) 交易日，1,000 次；40／60 日另報區塊 126 日敏感度。
- **區塊數量近似值（勘誤 3 修正命名）**：定義為「有效交易日數 ÷ 區塊長度」。**這只是數量的粗略近似，相除本身不證明區塊之間互相獨立**（重疊持有期、市場共同因子、波動叢聚都會讓實際有效資訊量更低）。文件與報告一律稱「區塊數量近似值」，不得稱「獨立區塊數」。
- **證據不足的明文允許**：重抽樣**不會增加原始獨立資訊量**。任一期間的區塊數量近似值 < 8 時，報告**必須**輸出「證據不足，不作結論」，不得以 bootstrap 區間充當統計證據。各期間的近似值列在報告首頁。
- **多重試驗**：所有權重組合與規則變體記錄；最終只在驗證段選一組。

### 13.3a 區塊門檻的必然後果（揭露表）

以 §13.1 的保留段有效日數與 §13.3 的區塊長度 `max(21, 3h)` 計算：

| 主要指標 | h | 有效日數 | 區塊長度 | 區塊數量近似值 | 是否達 8 | 結論 |
|---|---:|---:|---:|---:|---|---|
| 短線 | 10 | 395 | 30 | **13.2** | 是 | 可套用 §13.5 門檻 |
| 波段 | 20 | 385 | 60 | **6.4** | 否 | **必然判為證據不足** |
| 中期 | 40 | 365 | 120 | **3.0** | 否 | **必然判為證據不足** |

**這是刻意採用的保守政策，其產品後果必須寫在頁面上**：

> 以第一版的保留段長度，**波段（10–20 日）與中期（20–60 日）即使回測結果良好，也不會通過研究門檻**。這兩個期間第一版**只展示現況卦象與六爻依據，不輸出方向分數與多空候選名單**；三期間入口仍固定保留，並在頁面明示「資料量尚不足以驗證，等待更多獨立資料」。短線（5–10 日）是唯一可能在第一版通過門檻的期間，且仍須實際跑出結果才算通過。
